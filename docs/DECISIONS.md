# Decisions

Every decision is **provisional**. Revisit the ones marked with a trigger in the table, and treat anything tagged `SKELETON` in code as replaceable.

## Specified decisions

| # | Decision | Reason | Status | Revisit when |
|---|---|---|---|---|
| D1 | Python 3.11 only (`>=3.11,<3.12`) | Required by the user; keeps the toolchain consistent | provisional | The user changes the target |
| D2 | `venv` + `pip` + `pyproject.toml`, `src` layout | Simplest portable setup; the `src` layout prevents accidental imports from the working directory | provisional | Packaging needs grow |
| D3 | `pydantic` v2 for models | Validation at the boundaries, JSON round-trip, immutability | provisional | Performance problems |
| D4 | `networkx` for the in-memory graph only | Tested graph structure and neighbour queries; clustering logic stays ours | provisional | Clustering experiments |
| D5 | Own seed-and-attach algorithm, no ML or community detection initially | Explainable, deterministic, easy to test | provisional | Golden metrics show a gap |
| D6 | `botocore.stub.Stubber` for AWS tests; no `moto` | Exact service-model validation, no extra dependency, no hidden behaviour | provisional | Moto coverage becomes necessary |
| D7 | `hypothesis` for property tests | Invariants (determinism, partition) are best tested with generated inputs | provisional | None |
| D8 | Raw snapshots stored as JSON and replayable | Lets the builder run offline on stored data and makes failures reproducible | provisional | None |
| D9 | Four sources only (tags, stacks, topology, seeded CloudTrail) | Deterministic, low volume, mostly default-available | provisional | Evaluation shows gaps |
| D10 | Canonical key = (account_id, region, arn) | ARNs alone are not unique for some resources (such as S3 buckets) and account is needed for cross-account joins | provisional | None |
| D11 | Bounded affinity score | One contribution per edge type per cluster, so many weak edges cannot pile up | provisional | Tuning with golden data |
| D12 | Ruleset is versioned, hashed and in the output | Any result can be reproduced and compared across rule changes | provisional | None |
| D13 | `partition = "aws"` only | China and GovCloud partitions are out of scope until requested | provisional | A customer needs them |
| D14 | Parquet store is optional (extra) | Avoids a heavy dependency in the core path | provisional | Athena integration |

## Decisions made while building

| # | Decision | Reason | Status | Revisit when |
|---|---|---|---|---|
| D15 | `Workspace` lives in `models/workspace.py` | The approved account list is an input to the session provider, the probe and the builder. The layout in the spec did not name a module for it | provisional | A different scope object is supplied |
| D16 | Name hint lives in `graph/naming.py` | Keeps `build.py` to orchestration. The heuristic is the spec's, and is marked `SKELETON` because an LLM step may replace it later | provisional | The naming interface is designed |
| D17 | Tests ignore ruff `S105`, `S106`, `S311` and `S603` | Tests use obviously fake credentials, a seeded RNG for shuffles and synthetic data, and a fixed-argument subprocess for `PYTHONHASHSEED`. The spec already ignores `S101` in tests | provisional | The security lint set changes |
| D18 | A tag group is a star to the smallest member key. A group of one gets a self-edge | Same reason as container edges: connectivity without a quadratic number of edges. The self-edge keeps a lone tagged resource inside a seed | provisional | A different tag topology is wanted |
| D19 | A tag conflict excludes the resource from seeds and from attachment. It is unmapped with reason `tag_conflict` | The spec says the resource belongs to neither workload until a human decides. Letting it attach on topology would undo that | provisional | TAMs want a conflict to still be a candidate |
| D20 | Nested stacks are not merged into the parent | The spec says the child's resources belong to the child group and the parent link is recorded. The link is the attribute `parent_stack_id` plus a note, not a `STACK_MEMBER` edge | provisional | TAMs want one workload per root stack |
| D21 | Only an undeclared hub can be shared. Containers count distinct seeds on incoming container edges; a load balancer or target group counts them on outgoing `LB_TARGET` edges | Declared resources are seeds, not shared infrastructure. Direction stops a resource from looking shared just because it points at a popular container | provisional | Real data shows declared hubs that should be shared |
| D22 | Attachment is one pass. A link is a direct edge, or both resources pointing at the same container. Affinity is rounded to 6 decimal places. A tie goes to the lowest seed id | One pass is reversible and explainable. Rounding keeps the margin comparison stable. The lowest id is an order-independent tie break | provisional | A second pass would change golden scores |
| D23 | At most 10 evidence records are kept on a member (`MEMBER_EVIDENCE_CAP`) | Bounds output size. Marked `SKELETON` | provisional | TAMs need the full evidence list |
| D24 | `UnplacedReason` includes `no_edges` as well as `below_threshold` and `ambiguous` | A resource with no usable link is a different fact from one that scored below 0.6 | provisional | The report shape is fixed with TAMs |
| D25 | `BuildResult` carries `pending_refs` | An approved account that has not been collected yet must stay visible. It is not an external finding and it is not a member | provisional | Pending refs are folded into notes only |
| D26 | Degradation notes use `{source} {availability} in {account}` | One stable sentence per probe entry that is not `available`, so notes sort and diff cleanly | provisional | A structured degradation list is preferred |
| D27 | Mixed regions for one account and source: any region with data makes the account `partial`; otherwise denied beats error beats empty | A TAM should see that some data arrived. A total denial should not be hidden by an empty region | provisional | Region-level probe output is required |
| D28 | Stack collection uses `DescribeStackResources` | It returns the resource list in one call. The 100-resource ceiling is an assumption, recorded in `ASSUMPTIONS.md` | provisional | A stack larger than 100 resources appears |
| D29 | Collector request context is stored under payload keys that start with `_` | Normalisers need seed ids and target-group ARNs that are not fields of the AWS response. `has_data()` ignores those keys | provisional | Snapshots gain a separate metadata object |
| D30 | The CloudTrail call budget applies to one `collect` call. After a denial, later calls of that same operation are skipped | Bounds cost (D9) and avoids repeating a call that already failed | provisional | Budgets need to be per account across collectors |
| D31 | CloudTrail pass 2 keeps events only for principals that created a seed in pass 1 | Matches the seeded design: cost scales with known creators, not with every event name in the account | provisional | Undeclared creators turn out to matter |
| D32 | The stack resource itself is a declared member of its seed | The stack is the declaration. Omitting it made workload membership disagree with the stack the TAM can see | provisional | Stacks should be metadata only |
| D33 | `sources_used` is the union of the sources on member resources | A workload built from tags plus topology is not single-source, so the medium cap does not apply. This is what makes S2 high confidence | provisional | Source confidence should be counted differently |
| D34 | Pairwise precision is 1.0 when the build predicts no pairs. Coverage and the unmapped rate exclude shared infrastructure from the denominator | No predicted pair means no false positive. Shared infrastructure is reported separately, as the spec requires | provisional | A TAM-facing metric definition is agreed |
| D35 | Golden files record a human grouping, including an exclusive subnet with the workload that uses it. Rule weights were not changed to raise recall | The spec says to record the numbers, not to tune for a perfect score. S1, S6, S8 and S9 recall is below 1 for this reason | provisional | Real golden cases replace these files |
| D36 | S1–S11 raw snapshots are generated by `tests/fixtures/build_scenarios.py` from compact declarations | The pages still validate against botocore. Hand-editing thousands of response fields would drift | provisional | A fixture needs a shape the generator cannot express |
| D37 | An ambiguous or below-threshold resource that has a VPC goes to a residual group, not to `unmapped` | Matches the residual rule. S11's mystery instance is residual with reason `ambiguous`, and the note still says ambiguous. The unmapped rate therefore does not count it | provisional | TAMs want ambiguous resources listed only under unmapped |
| D38 | Each workload carries an edge list: store edges whose source is a member, sorted by source, destination and type | The page needs lines and edge tooltips. Sorting makes the list deterministic. LLM naming stays out of this path | provisional | A different edge subset is wanted on the page |
| D39 | `workload-graph ui` serves a local page. The operator types the account id. Collection runs only when that id matches the STS caller, using the ambient credential | The test pad is a personal account, not a member account reached through a role. The id is an input, not a value stored in the project | provisional | Approved-role collection is wired |
| D40 | Every member account gets a role named `TamReadOnly`. The default on `Workspace` is changed to match (it was `WorkloadGraphReadOnly`) | One fixed name is easy to copy into a customer account. The name is not per customer | provisional | A customer cannot use the fixed name |
| D41 | Credentials come in two modes. Ambient serves exactly one account and is checked with STS first. Assumed-role runs `sts:AssumeRole` with an ExternalId, one client per call, and a lock around the provider cache | Ambient is for the test pad only. The deployed service uses an ECS task role, so no IAM user exists. Sessions are per call because the default boto3 session is not thread-safe | provisional | Cross-account access is wired through another path |
| D42 | A failing account is isolated and noted in the build's notes. Only a failure in the joined build fails the job. Event details are codes, never exception messages | One denied account must not stop the other nineteen. Messages can carry account ids and ARNs | provisional | TAMs want a hard stop on any account failure |
| D43 | Workers are bounded (default 5). Snapshots join in account-id order, not completion order. The job's event log is in memory, numbered from 1, and a reader asks for events after the last number it saw | Results must not depend on thread scheduling. A dropped stream then loses nothing | provisional | Runs must survive a process restart (then persist under `out/runs/`) |
| D44 | The page starts a run through `POST /api/jobs` and follows it by long poll (`GET /api/jobs/<id>?after=N&wait=S`, capped at 25 s). Approve and reject go to `POST /api/jobs/<id>/review` | A long poll needs no streaming library and survives a dropped connection by asking for events after the last number it saw. The legacy `POST /api/build` stays for compatibility | provisional | Server-sent events or websockets are needed |
| D45 | Local test mode (no `--external-id`) accepts exactly one account, checked with STS. Deployed mode (`--external-id`) accepts up to 20 and assumes `TamReadOnly` in each | The test pad is one personal account with no member role. The deployed service holds the assume-role path | provisional | The test pad gets a `TamReadOnly` role of its own |
| D46 | Approve and reject are kept per run, in memory, and are only accepted after the build settles. Cost review will run only on approved workloads | The TAM's gate comes before any cost work. Rejected workloads count as unattributed spend (later step) | provisional | Decisions must survive a restart (then persist under `out/runs/`) |
| D47 | Accounts typed on the page are remembered in the browser's local storage, up to 50, and offered as a dropdown. They are never written to the project | The operator asked for a dropdown of past entries. Browser storage keeps account ids out of the repo | provisional | A shared team list is needed |
| D48 | AWS does not let root credentials call `sts:AssumeRole`. The test pad therefore uses a dedicated IAM user, `wg-test-runner`, whose only permission is `sts:AssumeRole` on `TamReadOnly`. The deployed service uses its ECS task role, which is also not root | The first live assume-role attempt with root keys failed with "Roles may not be assumed by root accounts". The test user mirrors the task role | provisional | The test pad gets its own non-IAM route (for example SSO) |
| D49 | The role `TamReadOnly` trusts only the test-runner user, requires `sts:ExternalId`, and carries an inline read-only policy listing exactly the collector calls. The ExternalId and the runner key live outside the repo, in `~/.config/workload-graph/` with mode 600 | Least privilege for a customer role, and no secret in the repo. Rotate the runner key after the test | provisional | The collector list changes (update the policy with it) |
| D50 | A collector's own notes, which carry the error code, are copied into the run's notes, attributed to the account and source | A transient tags failure was visible only as "tags error" with no code. A TAM must see why a source is missing | provisional | Notes grow too large for a review screen |
| D51 | One account, or one worker, is collected on the calling thread with no pool. Threads start only when there are two or more accounts and more than one worker | Concurrency adds nothing for one account. A single-account run must not depend on thread behaviour | provisional | A single run needs to be cancellable (a pool may then be needed) |
| D52 | Every AWS client is built with a 5 s connect timeout, a 30 s read timeout and one retry. After one connection-level failure (DNS, connect, timeout) the recorder refuses later calls to the same endpoint with no I/O and writes one note. Other endpoints are not affected | A host that did not resolve made the run appear stuck: one failing call per seed, each with the default retries and no timeout. Now it costs one call | provisional | A source needs longer than 30 s for one call |
| D53 | Collectors report `source_started` and `source_done` (with status code) through a progress callback, and these appear in the job's event log and on the page | A slow source must look like progress, not a frozen page | provisional | The event log grows too large for one run |
| D54 | Runs are saved under `out/runs/<run id>/run.json` (gitignored) at start, when they settle and on every decision, written through a temporary file and a rename. A run saved before it settled is restored as `failed` with detail `interrupted`. `GET /api/runs` lists them newest first | Reviews must survive a restart, and the cost review and Ledger read approved runs. `out/` is gitignored, so account ids stay out of the repo | provisional | Runs are shared between TAMs (then a database) |

## Cost layer (from `COST_FINDINGS_BRIEF.md`)

| # | Decision | Reason | Status | Revisit when |
|---|---|---|---|---|
| F-D1 | `Decimal` everywhere for money, ratios and percentages | Floats corrupt sums and break exact reconciliation | provisional | Never |
| F-D2 | Cost snapshots load with `parse_float=Decimal`; collectors decimalise responses before storing | boto3 parses JSON doubles as floats | provisional | Never |
| F-D3 | Cents rounding only at presentation (`ROUND_HALF_UP`) | Avoids accumulated rounding error | provisional | Never |
| F-D4 | Separate `FindingsRuleset` with its own version and hash | The workload `Ruleset` stays untouched; both hashes appear in the report | provisional | Rulesets merge |
| F-D5 | Attribution ladder: tag > resource-level > sole-workload account > none | Strongest and longest window first; tag and resource-level both shown | provisional | Better evidence |
| F-D6 | Buckets: workload, shared, unplaced, unknown, no_resource_id, unexplained | Every dollar of the window total lands somewhere | provisional | None |
| F-D7 | No cost allocation to shared infrastructure (`# DECISION-PENDING:`) | Allocation is a business decision | provisional | Customers specify a rule |
| F-D8 | Month-over-month on complete months only; current month alone, estimated | Partial months mislead | provisional | None |
| F-D9 | Account-level drivers only | Two group-bys cannot hold workload, service and account | provisional | Resource-level data is reliable |
| F-D10 | Commitment recommendations are account-level | They are purchases, not resource changes | provisional | None |
| F-D11 | The hub's deduplicated summary is the only savings total | Item sums double count | provisional | None |
| F-D12 | Lexicographic ordering inside sections; no weighted score | No invented weights | provisional | TAM feedback |
| F-D13 | Confidence = min(workload confidence, method confidence) | Never inflates | provisional | Calibration data |
| F-D14 | The guardrail blocks causal language; "driven by" only for drivers | No finding supports a cause | provisional | A finding gains causal evidence |
| F-D15 | Template narrator is default and fallback; the model narrator is a stub | Deterministic and testable | provisional | The model step is approved |
| F-D16 | Snapshot cache keyed by (source, access account, label, params, as_of), 24-hour TTL, injected clock | Limits per-request cost | provisional | Pricing changes |
| F-D17 | Resource-level window 13 days | The documented limit is 14; edge semantics unverified | provisional | The bound is verified |
| D55 | Live UI and wiring are built although the brief excludes them | The operator asked for cost review after approval and a Ledger screen. The offline core was built to the brief first | provisional | The brief is revised |
| D56 | Cost sources are not added to the graph `SOURCES`; the graph loader skips `cost_explorer.json` and `cost_optimization_hub.json` silently. `COST_SOURCES` lists them | The graph probe must not report cost files as unknown or missing | provisional | One loader serves both |
| D57 | Cost payload keys are `"<Operation>:<label>"`, and each snapshot carries `_labels` with a status per call (ok, empty, denied, not_enabled, partial, error, skipped) | Coverage must show `not_enabled` per call, which the snapshot status cannot | provisional | Snapshots gain structured metadata |
| D58 | `CallRecorder` takes an optional `not_enabled` matcher, checked before the denial check | The "not enabled" errors are unverified (assumption 4); one configurable hook keeps that in the ruleset | provisional | The errors are verified |
| D59 | A denial is remembered per operation, so a second label on the same operation is skipped | IAM grants per action, so the second call would fail the same way | provisional | Labels need separate permissions |
| D60 | The aggregate spend scope exists only with more than one account | With one account it would duplicate the account finding | provisional | TAMs want it always |
| D61 | Members of workloads that were not approved count as `unplaced`; tags come from an optional map built from graph snapshots | Only approved workloads are reviewed (D46). `BuildResult` holds no tags | provisional | `BuildResult` carries tags |
| D62 | `build_result_sha256` hashes the build result with every list sorted | Report bytes must not depend on input order (F16) | provisional | List order becomes meaningful |
| D63 | Money mismatch raises `CurrencyMismatchError`; tests stay flat in `tests/unit/` with builders in `tests/wg_cost_builders.py`; no frozen scenario JSON; boto3-stubs extras not added | Matches existing conventions; one fixture source | provisional | Fixtures need freezing |
| D64 | The guardrail ignores dates, finding ids, account ids in scope, workload names and the cited findings' non-numeric strings before checking bare integers. Money and percentages are checked first | Service names such as "Route 53" and the unit "USD" must not count as numbers or hide them | provisional | A false accept is found |
